# Nobz Beats

A music streaming single-page app built with React 18, Vite 5, Tailwind CSS 3, and Convex (serverless DB, storage, and HTTP actions). Features a vinyl-themed UI with glitch logo, parallax covers, audio player with visualizer, and playlist management.

## Quick Start

```bash
npm install
npm run dev       # Start Vite dev server (client only)
npx convex dev    # Start Convex dev server (separate terminal)
npm run build     # Build for production
```

## Tech Stack

| Layer | Technology |

## Data Flow

### Convex Database Schema (`convex/schema.js`)

Two tables with `createdAt: v.number()` timestamps set on insert:

**`tracks`** — each track document:
- `title` (string, required)
- `description` (optional string)
- `artwork` (optional URL string)
- `artworkStorageId` (optional Convex Storage ID — for cleanup on update/delete)
- `src` (optional audio URL)
- `srcStorageId` (optional Convex Storage ID)
- `type` (optional string — `"single"`, `"remix"`, or `"album"`)
- `albumId` (optional foreign key to `albums`)
- `createdAt` (number)

**`albums`** — each album document:
- `title` (string, required)
- `description` (optional string)
- `artwork` (optional URL string)
- `artworkStorageId` (optional Convex Storage ID)
- `createdAt` (number)

### Client-Side Data

- `App.jsx` uses `useQuery('functions/tracks:listTracks')` and `useQuery('functions/albums:listAlbums')` to fetch all data
- Raw tracks are normalized into `singles`, `remixes`, `albums`, `allTracks`, and `latestItems` based on `type` and `albumId` fields
- Artwork paths from older DB records that reference `/assets/...` are stripped to the root path (Vite's `publicDir: 'assets'` serves them at `/`)
- The latest 5 items (tracks + albums) are sorted by `createdAt` for the `Latest` view

### Uploads

1. Client sends files to Convex HTTP actions via `src/lib/storage.js`
2. `POST /upload/artwork` — validates `image/*`, max 5MB, returns `{ url, storageId }`
3. `POST /upload/audio` — validates `audio/*`, max 25MB, returns `{ url, storageId }`
4. Both endpoints accept `multipart/form-data` and raw `arrayBuffer` uploads
5. Supports both `storage.put()` (legacy) and `storage.store()` (newer API)
6. On update/delete, server functions clean up the old Convex Storage objects

## Routing

Client-side routing via the History API (no React Router):

| Route | Component | Description |
|---|---|---|
| `/latest` | `Latest` | Recent tracks and albums |
| `/singles` | `Singles` | Standalone single tracks |
| `/albums` | `Albums` | Albums with grouped tracks |
| `/remixes` | `Remixes` | Remix tracks |
| `/alltracks` | `AllTracks` | Flat scrollable track list |
| `/about` | `About` | Placeholder |
| `/connect` | `Connect` | Placeholder |
| `/admin` | `Admin` | Login-gated dashboard |

The Nav component uses `history.pushState()` + `PopStateEvent` dispatch. The `App` listens for `popstate` and updates the route state.

## Playback & State

- **Playlist and current track** live in `App.jsx` as `useState`
- `playTrack(track)` — sets current track and starts playback
- `addToPlaylist(track)` — appends to queue, no duplicates
- `playAlbum(album)` — replaces playlist with album tracks, starts first track
- `shufflePlaylist()`, `clearPlaylist()`, `removeFromPlaylist(id)`, `reorderPlaylist(from, to)` — playlist management
- Vinyl animation state is coordinated globally via `src/lib/vinly.js` — an `EventTarget` on `window.__vinylBus` with per-track `{ out, spinning }` state. The `Player`, `Cover`, and `AlbumItem` components all subscribe to this bus so the vinyl sleeve/rotation stays in sync.

## Environment Variables

| Variable | Required | Purpose |
|---|---|---|
| `VITE_CONVEX_URL` or `VITE_CONVEX_SITE_URL` | Yes | Convex deployment URL for client queries |
| `VITE_ADMIN_USER` | No | Admin login username (default: `admin`) |
| `VITE_ADMIN_PASSWORD` | No | Admin login password (default: `admin`) |

Example `.env.local`:
```text
VITE_CONVEX_URL=https://dev-your-site.convex.cloud
VITE_ADMIN_USER=admin
VITE_ADMIN_PASSWORD=your-password
```

## Admin Dashboard

The admin UI at `/admin` is protected by a simple login gate (credentials checked against env vars, auth persisted in `localStorage`). Tabs provide:
- **Tracks** — list all tracks, edit title/description/type/album, delete
- **Albums** — list all albums, edit, delete
- **Add Track** — upload artwork + audio, set type and optional album
- **Add Album** — create new album with artwork

Each admin section is wrapped in an `ErrorBoundary` that catches Convex function errors and shows recovery guidance.

## Coding Conventions

See `AGENTS.md` for comprehensive rules covering:
- **Tailwind-first styling** — utility classes before custom CSS, no inline styles for static values, no `!important`
- **React component architecture** — default exports, PascalCase files, no context/redux
- **JavaScript style** — no semicolons, single quotes, 2-space indent, defensive coding
- **Convex patterns** — null normalization, createdAt timestamps, storage cleanup on mutations

## Notes

- **SPA routing**: Vercel's `vercel.json` rewrites all routes to `/index.html`. For other hosts, configure similar SPA fallback behavior.
- **Assets**: Vite's `publicDir` is set to `assets/`, so `/artwork/default.png` serves from `assets/artwork/default.png`.
- **Unused deps**: `express`, `cors`, `multer` in `package.json` are leftovers and can be removed.
- **Cal Sans font**: Loaded from Google Fonts (may need a fallback if unavailable).
- **Convex dev**: Run `npx convex dev` in a separate terminal for local backend. The `convex/_generated/` directory is auto-populated.
